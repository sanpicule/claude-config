### 総評
ログイン処理のリファクタは妥当だが、エラー時の挙動とテスト不足が気になる。

### 指摘事項
| # | 重要度 | ファイル:行         | 内容                                                |
|---|--------|---------------------|-----------------------------------------------------|
| 1 | 高     | src/auth/login.ts:42| 例外を握りつぶしている。少なくともログに残す。       |
| 2 | 中     | src/auth/login.ts:88| `any` 型が広がっている。返り値の型を明示する。       |
| 3 | 低     | src/auth/login.ts:5 | 未使用 import が残っている。                         |

### 改善案
```ts
// 例: 例外を握りつぶさず、再 throw する
try {
  await verifyToken(token);
} catch (err) {
  logger.warn({ err }, "token verification failed");
  throw err;
}
```

### 良い点
- 認証ロジックが 1 ファイルに集約され、責務が明確になった。
- 既存テストを壊さないように差分が最小化されている。
