# セキュリティ ルール

## 秘匿情報

- `.env` / 鍵 / トークンはコミットしない。誤って入れた場合は履歴から除去 + 失効が必須。
- 秘匿値はコード中にハードコードしない。環境変数 or シークレット管理サービス経由のみ。
- ログ・例外メッセージ・URL クエリに秘匿値を出力しない。

## 入力 / 出力

- 外部入力 (HTTP / WebSocket / ファイル / コマンド引数) はすべて検証してから使う。
- SQL は必ずパラメータ化クエリ。文字列連結で組み立てない。
- HTML 出力は自動エスケープを既定とし、`dangerouslySetInnerHTML` などはレビュー必須。
- シェル実行は引数配列で渡す。`shell=True` / 文字列結合は禁止。

## 認証 / 認可

- 認可チェックは API レイヤで必ず行う (フロントだけに頼らない)。
- セッション / トークンは HttpOnly + Secure + SameSite を既定にする。
- 権限テーブルは「明示的に許可」されたものだけ通す (デフォルト拒否)。

## 依存

- 新しい依存を追加するときは: メンテ状況・直近 1 年のリリース・OSS ライセンスを確認。
- `npm audit` / `pip-audit` / `osv-scanner` などの結果は CI で見える化する。
