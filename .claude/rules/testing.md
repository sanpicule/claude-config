# テスト ルール

## 原則

- 1 テスト = 1 振る舞い。複数アサートしてもよいが、目的は 1 つに絞る。
- テスト名は「〜のとき〜を返す / 〜を呼ぶ」のように振る舞いを書く。実装詳細を書かない。
- 構造は Arrange / Act / Assert を意識し、空行で 3 ブロックに分ける。

## モック・スタブ

- ネットワーク・DB・時刻・乱数は必ずモック化する。
- ライブラリ全体を `vi.mock('lib')` で潰すのではなく、必要な関数だけ差し替える。
- モックの再利用は最小限。テストごとに `beforeEach` でリセットする。

## カバレッジ

- 行カバレッジは指標であり目的ではない。境界値・異常系・例外を優先して書く。
- 触っていない既存コードを「カバレッジのため」だけにテストしない。

## スナップショット

- スナップショットは UI / 大きな構造のみ。プリミティブ値や 1〜2 行の構造には使わない。
- 失敗時に「とりあえず更新」してはいけない。差分の理由を必ず確認する。
