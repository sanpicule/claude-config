# コーディング規約

## 命名

- 変数・関数: `camelCase` (Python は `snake_case`)。
- 型・クラス・コンポーネント: `PascalCase`。React の Props は `<Name>Props` 形式。
- 定数: `UPPER_SNAKE_CASE`。マジックナンバーは必ず定数に切り出す。
- ブール値: `is` / `has` / `can` プレフィックスで意味を明確に (`isLoading`, `hasError`)。
- ファイル名: ディレクトリ規約に合わせる (例: コンポーネントは `PascalCase.tsx`、ユーティリティは `kebab-case.ts`)。

## 型 / 静的解析

- 型システムがある言語では `any` / `unknown` の濫用を禁止する。`unknown` + 型ガードで絞る。
- 公開 API (export される関数・クラス) は引数と戻り値の型を明示する。
- Linter / Formatter は CI で必ず通す。ローカルでは保存時自動整形を推奨。

## 関数・モジュール設計

- 1 関数 1 責任。30〜50 行を超えたら分割を検討する。
- 引数が 4 個を超えたらオブジェクト引数に集約する (順序ミス防止)。
- 副作用 (I/O、グローバル状態書き換え) は呼び出し側から見える形に出す。隠さない。
- 例外は捕捉したら必ず処理する。`catch (e) {}` で握りつぶさない。

## コメント / ドキュメント

- コメントは「なぜ」を書く。「何を」はコードと命名で表現する。
- 「TODO」「FIXME」には起票したチケット番号 or 期日を併記する。
- 公開 API には docstring / JSDoc を書く (引数・戻り値・例外)。

## 禁止事項

- マジックナンバー / マジック文字列の散在。
- 同じロジックの重複 (3 箇所目で関数化を検討)。
- console.log / print デバッグの本番コミット。
- 大きなコメントアウトコードの放置 (Git 履歴に任せる)。
